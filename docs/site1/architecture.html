🏗️ Arquitetura do Oríon Framework

A arquitetura do Oríon é inspirada em Clean Architecture e nos princípios SOLID, garantindo isolamento de camadas, testabilidade e facilidade de extensão.

Princípios de Design

Clean Architecture

  • Independência de frameworks: o Core não depende de bibliotecas externas.
  • Testabilidade: regras de negócio testáveis sem dependências externas.
  • Independência de interface: a CLI pode ser trocada sem impacto no Core.
  • Independência de banco: conectores plugáveis via interfaces.

SOLID

Single Responsibility Principle

  • Pipeline: orquestra a sequência de nodes.
  • Node: encapsula uma transformação.
  • Catalog: mantém o mapeamento de datasources.
  • Connector: implementa a persistência específica.

Open/Closed Principle

  • Novos conectores podem ser adicionados sem alterar código existente.
  • Nodes personalizados são apenas funções Python adicionais.

Liskov Substitution Principle

  • Qualquer implementação de IDataConnector substitui outra.
  • Qualquer implementação de ILogger substitui outra.

Interface Segregation Principle

  • Interfaces pequenas e focadas (IDataConnector, ILogger).
  • Classes não são obrigadas a implementar métodos desnecessários.

Dependency Inversion Principle

  • Pipeline (alto nível) depende de abstrações.
  • Conectores (baixo nível) implementam as abstrações.

Fluxo de Execução

  1. CLI recebe comando 
    # application/cli/commands.py
orion run --module X --catalog Y
  2. Carrega catalog 
    catalog = DataCatalog.from_yaml("catalog.yml")
  3. Cria contexto 
    context = OrionContext(catalog=catalog, logger=ConsoleLogger())
  4. Carrega pipeline 
    pipeline = _load_pipeline(module_path, func_name)
# Instância de Pipeline com lista de Nodes
  5. Executa use case 
    runner = PipelineRunner()
runner.run(pipeline, context)
# Internamente aciona RunPipelineUseCase.execute()
  6. Executa nodes 
    for node in pipeline.nodes:
    inputs = []
    for input_name in node.inputs:
        if input_name in data:
            inputs.append(data[input_name])
        else:
            inputs.append(context.catalog.load(input_name))

    outputs = node.run(context, *inputs)

    for output_name, value in zip(node.outputs, outputs):
        data[output_name] = value
        if context.catalog.exists(output_name):
            context.catalog.save(output_name, value)

Design Patterns

  • Builder: PipelineBuilder para compor pipelines.
  • Strategy: IDataConnector para múltiplas fontes.
  • Dependency Injection: OrionContext injeta recursos.
  • Template Method: Pipeline.run() define o algoritmo.
  • Factory: DataCatalog.from_yaml() carrega configurações.

Extensibilidade

Novo conector

  1. Implementar IDataConnector: 
    class MyConnector(IDataConnector):
    def load(self, **kwargs) -> Any:
        ...

    def save(self, data, **kwargs) -> None:
        ...
  2. Registrar no catalog: 
    catalog.connectors["my_type"] = MyConnector()
  3. Usar no catalog.yml: 
    my_dataset:
  type: my_type
  param1: value1

Novo logger

  • Implementar a interface ILogger.
  • Instanciar o logger desejado no OrionContext.

Testabilidade

Mock de dependências

mock_catalog = MagicMock()
mock_catalog.load.return_value = pd.DataFrame(...)
context = OrionContext(catalog=mock_catalog)

result = my_node_function(context, df)

Testes de integração

catalog = DataCatalog.from_yaml("test_catalog.yml")
context = OrionContext(catalog=catalog)
pipeline.run(context)

Performance e Otimizações

  • Estado em memória: outputs ficam disponíveis para nodes seguintes.
  • Lazy loading: conectores são criados somente quando necessários.
  • Execução sequencial: facilita debugging e garante dependências.

Segurança

  • Credenciais do Databricks ficam em ~/.orion/databricks.yml com permissões restritas.
  • Arquivo nunca deve ser versionado.
  • Suporte a variáveis de ambiente para segredos.
  • Validação de inputs com type hints e checagens de schema.
