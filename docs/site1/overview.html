Visão Geral do Oríon Framework

Conheça os objetivos, princípios de arquitetura e o fluxo completo de execução que sustentam o Oríon Framework. Esta página condensa os principais pontos da documentação oficial.

Por que usar o Oríon?

O Oríon foi projetado para acelerar a criação de pipelines de dados declarativos, resilientes e totalmente observáveis. O framework aplica Clean Architecture e princípios SOLID para garantir uma separação clara de responsabilidades.

  • Clean Architecture: camadas independentes com contratos definidos.
  • Type Safety: uso consistente de type hints e validações.
  • Observabilidade: logging contextual embutido em cada node.
  • Extensibilidade: conectores plugáveis para múltiplos backends.
  • Idempotência: execução determinística para pipelines reproduzíveis.

Arquitetura em Camadas

A arquitetura é organizada em três camadas principais seguindo a regra de dependência: camadas externas dependem apenas de interfaces expostas por camadas internas.

Fluxo de Dados

O pipeline é inicializado via CLI, carrega configurações do catálogo e executa nodes puros dentro de um OrionContext. Cada node pode carregar dados a partir de conectores configurados e persistir resultados automaticamente. 

graph LR
    CLI[CLI: orion run] --> Catalog[Carregar catalog.yml]
    Catalog --> Context[Criar OrionContext]
    Context --> Builder[PipelineBuilder]
    Builder --> Runner[PipelineRunner]
    Runner --> Nodes[Executar Nodes]
    Nodes --> Save[Catalog.save opcional]

Conceitos Fundamentais

  • Nodes: funções puras executadas com context e inputs.
  • Catalog: abstrai carregamento e persistência de dados.
  • Context: provê logging, configurações e acesso a conectores.
  • PipelineBuilder: descreve dependências entre nodes.
  • Datasets: contrato para entradas e saídas tipadas.
