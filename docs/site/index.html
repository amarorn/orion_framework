Layered Domain Boundaries

A triad of core, application, and infrastructure mirrors medieval celestial charts—each orbit has a purpose, and data flows are explicitly governed to avoid tangled dependencies.

  • Entities and use cases remain pure Python.
  • Builders and runners coordinate execution.
  • Connectors and catalog entries handle all I/O.

Limites de Domínio em Camadas

A tríade de core, application e infrastructure espelha cartas celestes medievais — cada órbita tem um propósito e os fluxos de dados são governados explicitamente para evitar dependências emaranhadas.

  • Entidades e casos de uso permanecem em Python puro.

  • Conectores e o catálogo cuidam de toda a entrada e saída.

Catalog-First Observability

Orion Context centralizes catalog access, logging, and configuration, echoing observatories mapping the night sky: every dataset and node output has a traceable source and destination.

Auto-saving ensures outputs named after catalog datasets persist without additional boilerplate.

Observabilidade Centrada no Catálogo

O Orion Context centraliza acesso ao catálogo, logging e configuração, como observatórios cartografando o céu noturno: cada dataset e output de node tem origem e destino rastreáveis.

O autosave garante que outputs com nomes de datasets do catálogo sejam persistidos sem boilerplate extra.

Observabilidad Centrada en el Catálogo

Orion Context centraliza el acceso al catálogo, el logging y la configuración, como observatorios que cartografían el cielo nocturno: cada dataset y output de un node tiene un origen y destino trazables.

El autosave garantiza que los outputs con nombres de datasets del catálogo se persistan sin código adicional.
