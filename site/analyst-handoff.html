Guia de Handoff Analista

Alinhe analistas e engenheiros nas entregas Orion com um handoff orientado a SQL, mantendo template compartilhado e critérios de aceite claros.

How to Use the Handoff Template

The template bridges business questions and Orion implementation. Follow the steps to keep requirements, SQL and validation aligned across teams.

Download the template using the button below and keep it attached to your ticket so engineering can trace context, SQL draft and validation in one place.

1. Context Sheet

Capture the business goal, datasets, grain, freshness and constraints.

  • List catalog aliases when known
  • Attach sample rows or screenshots
  • Identify stakeholders and compliance rules

2. Requirements → SQL

Draft the core query using catalog aliases and note open questions.

  • Highlight joins, filters and calculations
  • Use comments to surface doubts
  • Ensure ordering and limits are explicit

3. Impact Matrix & Validation

Map result columns to sources and define the acceptance check.

  • Flag new connectors or catalog entries
  • Assign ownership for each dataset
  • Describe one deterministic validation scenario

Como Usar o Template de Handoff

O template conecta a pergunta de negócio à implementação no Orion. Siga os passos para manter requisitos, SQL e validação alinhados entre as equipes.

Baixe o template pelo botão abaixo e mantenha-o anexado ao ticket para que a engenharia tenha contexto, SQL esboçada e validação em um único lugar.

1. Ficha de Contexto

Registre objetivo, datasets, granularidade, recorte temporal e restrições.

  • Informe aliases do catálogo quando existirem
  • Anexe linhas de exemplo ou prints esperados
  • Identifique stakeholders e regras de compliance

2. Requisitos → SQL

Esboce a consulta principal usando aliases do catálogo e sinalize dúvidas.

  • Evidencie joins, filtros e cálculos
  • Use comentários para destacar pontos em aberto
  • Garanta que ordenações e limites estejam claros

3. Matriz & Validação

Mapeie colunas do resultado para suas origens e defina o teste de aceite.

  • Sinalize conectores ou entradas novas no catálogo
  • Associe responsáveis por dataset
  • Descreva um cenário determinístico de validação

Steps for Analysts

  1. Download the template and duplicate it for your request.
  2. Fill the context sheet and add sample data or visuals.
  3. Draft the SQL query, marking uncertainties with comments.
  4. Complete the impact matrix and validation scenario.
  5. Attach the filled template to the ticket opened for engineering.

Keep the SQL draft runnable in your exploration environment whenever possible; share query IDs or notebooks so engineers can reproduce the exact logic.

The more precise the SQL draft, the faster the engineering team can build or adjust nodes and catalog entries.

Passos para Analistas

  1. Baixe o template e crie uma cópia para a sua demanda.
  2. Preencha a ficha de contexto e inclua dados ou visuais de exemplo.
  3. Esboce a query SQL, sinalizando dúvidas com comentários.
  4. Complete a matriz de impacto e o cenário de validação.
  5. Anexe o template preenchido ao ticket aberto para engenharia.

Mantenha a SQL executável no ambiente de exploração sempre que possível; compartilhe IDs de consultas ou notebooks para que a engenharia reproduza exatamente a lógica.

Quanto mais preciso o esboço SQL, mais rápido o time de engenharia consegue criar nodes e ajustar o catálogo.

Steps for Engineers

  1. Review the context, SQL draft and validation scenario.
  2. Confirm catalog aliases and identify missing datasets.
  3. Translate the SQL into Orion nodes, following the provided example.
  4. Update the catalog and pipeline builder with the agreed outputs.
  5. Run the validation scenario and share results with the analyst.

Document any deviations from the original SQL directly in the template so analysts and stakeholders understand adjustments made during implementation.

Keep the template updated during implementation to capture additional assumptions or changes agreed with stakeholders.

Passos para Engenheiros

  1. Revise o contexto, esboço SQL e cenário de validação.
  2. Confirme aliases do catálogo e identifique datasets faltantes.
  3. Traduza a SQL em nodes Orion conforme o exemplo fornecido.
  4. Atualize catálogo e pipeline builder com os outputs acordados.
  5. Execute o teste de validação e compartilhe o resultado com o analista.

Registre no template qualquer ajuste em relação à SQL original para que analistas e stakeholders entendam as decisões tomadas na implementação.

Mantenha o template atualizado durante a implementação para registrar premissas adicionais ou ajustes combinados com os stakeholders.
