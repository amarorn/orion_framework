Arquitetura

Arquitetura do Orion Framework

A arquitetura do Orion é inspirada em Clean Architecture e nos princípios SOLID, garantindo isolamento de camadas, testabilidade e facilidade de extensão.

Overview

Orion follows Clean Architecture principles with three main layers:

  • Core Layer: Entities and interfaces, no external dependencies.
  • Application Layer: Use cases, builders, runners and CLI commands.
  • Infrastructure Layer: Concrete implementations (connectors, logging, persistence).

Design Principles

SOLID

  • Single Responsibility: Each class has one reason to change.
  • Open/Closed: Open for extension, closed for modification.
  • Liskov Substitution: Implementations are interchangeable via interfaces.
  • Interface Segregation: Small, focused interfaces.
  • Dependency Inversion: Depend on abstractions, not concretions.

Execution Flow

  1. CLI receives command: orion run --module X --catalog Y
  2. Load catalog from YAML file
  3. Create OrionContext with catalog and logger
  4. Load pipeline module
  5. Execute use case: RunPipelineUseCase.execute()
  6. Execute nodes sequentially, managing inputs/outputs

Visão Geral

O Orion segue os princípios de Clean Architecture com três camadas principais:

  • Core Layer: Entidades e interfaces, sem dependências externas.
  • Application Layer: Casos de uso, builders, runners e comandos CLI.
  • Infrastructure Layer: Implementações concretas (conectores, logging, persistência).

Princípios de Design

SOLID

  • Single Responsibility: Cada classe tem uma razão para mudar.
  • Open/Closed: Aberto para extensão, fechado para modificação.
  • Liskov Substitution: Implementações são intercambiáveis via interfaces.
  • Interface Segregation: Interfaces pequenas e focadas.
  • Dependency Inversion: Depender de abstrações, não de concretizações.

Fluxo de Execução

  1. CLI recebe comando: orion run --module X --catalog Y
  2. Carrega catalog do arquivo YAML
  3. Cria OrionContext com catalog e logger
  4. Carrega módulo da pipeline
  5. Executa caso de uso: RunPipelineUseCase.execute()
  6. Executa nodes sequencialmente, gerenciando inputs/outputs
